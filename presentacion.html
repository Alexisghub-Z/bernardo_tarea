02 · El problema
¿Por qué
existe este
sistema?
1
Información repartida en muchos archivos
Excel, CSV, PDF, TXT, JSON — sin lugar centralizado para consultarlos todos juntos.
2
Sin indicadores en tiempo real
Nadie sabe cuántas dosis se aplicaron, qué municipios están rezagados ni cuántos establecimientos siguen activos.
3
Datos atrapados localmente
Sin base de datos central, la información no tiene respaldo ni se puede rastrear históricamente.
4
Nombres de estados inconsistentes
"oax", "OAX", "Oaxaca", "Oaxaca de Juárez" — el mismo estado escrito de 10 formas distintas imposibilita comparar datos.
03 · Objetivo general
Unificar, procesar
y visualizar datos de
vacunación nacional

08 · Persistencia
Integración MongoDB Atlas
vacunacion_db · Cluster0
¿Por qué MongoDB?
Los registros de vacunación no siempre tienen las mismas columnas. MongoDB guarda cada fila como un documento flexible. Al estar en la nube, los datos persisten aunque se cierre la aplicación.
Método principal
class MongoDBConnector:
  def guardar_datos(self, df, fuente):
    # Chunks para archivos grandes
    for i in range(0, total, 10000):
      chunk = df.iloc[i:i+10000]
      datos = chunk.to_dict('records')
      for reg in datos:
        reg['fecha_insercion'] = now()
        reg['fuente'] = fuente
      collection.insert_many(datos)
Colecciones

10 · Sistema de alertas
Semáforos
de KPIs
Cada indicador se compara automáticamente contra rangos predefinidos y cambia de color. Cualquier persona puede detectar problemas de un vistazo, sin necesidad de interpretar números.
Verde — Óptimo
Supera el umbral alto. Ej: >1M dosis, >20 entidades.
Amarillo — Atención
Entre umbral medio y alto. Ej: 100K–1M dosis.
Rojo — Alerta
Por debajo del mínimo. Requiere acción. Ej: <100K.

13 · Nueva fuente de datos
Importar
desde URL
El usuario pega cualquier enlace directo a un archivo CSV o Excel (GitHub, Our World in Data, datos.gob.mx, etc.) y el sistema lo descarga automáticamente, lo guarda en un archivo temporal y lo procesa a través del pipeline ETL sin ningún paso adicional.
URL de ejemplo para prueba
https://raw.githubusercontent.com/
owid/covid-19-data/master/public/
data/vaccinations/country_data/
Mexico.csv
Flujo de integración
1
Usuario pega la URL
Campo de texto en pantalla EXTRAER. Acepta cualquier URL pública que apunte a .csv, .xlsx, .xls o .xlsm.
2
Descarga con requests en hilo separado
Streaming en chunks de 64 KB. Sin bloquear la interfaz. Barra de estado en tiempo real.
3
Archivo temporal → Pipeline ETL
El archivo se guarda en tempfile y se inyecta directamente como fuente del pipeline: Extraer → Transformar → Cargar a MongoDB.
4
KPIs actualizados automáticamente
Los datos descargados alimentan el Dashboard con los mismos 14 KPIs, filtros y semáforos que cualquier otra fuente.
